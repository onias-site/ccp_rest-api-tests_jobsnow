ao criar codigo, a variável já tem de estar extraída. Exemplo: em vez de: "metodoQueRecebeString(humano.getOlho(Lados.Esquerdo).getCor().toString());" o correto a se fazer é: "Olho olho = humano.getOlho(Lados.Esquerdo); Cor cor = olho.getCor(); String str = olho.toString(); metodoQueRecebeString(str);"... Isso vale para expressões dentro de ifs, expressões em loops, em returns, etc.
strings literais devem ser evitadas, em seu lugar, sempre se deve criar um item de algum enum interno daquele arquivo java que está sendo trabalhado e este enum interno deve implementar a interface. Em casos de strings que possuem caracteres especiais inviabilizando a criação deste enum, ele deve ser criado assim mesmo, porém, sobreescrevendo o método "getValue", exemplo: uma string literal "S/A" deve ser substituída por um item de enum enum Fields implements CcpJsonFieldName{ S_A{ public String getValue(){return "S/A";}}}
antes de criar qualquer item de enum, tem-de verificar sua prévia existência nos enums centralizadores que são JnJsonCommonsFields, VisJsonCommonsFields, CcpJsonCommonsFields, JnJsonInstantMessengerFields ou qualquer outro enum que possa vir a existir no futuro que seja constatado como centralizador.
